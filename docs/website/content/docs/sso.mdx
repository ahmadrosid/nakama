---
title: "SSO (OIDC)"
description: "Sign in to Nakama through an external OpenID Connect provider, such as Pocket ID."
---

SSO lets your team sign in to Nakama with an identity provider you already run instead of a second password. Any OpenID Connect provider works — Pocket ID, Authentik, Keycloak, Zitadel. The login page gets a **Continue with** button; the provider handles the password or passkey prompt.

Accounts still live in Nakama. The provider proves who the person is; Nakama decides whether that person gets an account and which organization it lands in.

## What you need first

- A running **OIDC provider** that both the browser and the Nakama server can reach.
- The **client ID and client secret** from a new OIDC client on that provider.
- The **callback URL** to register there: `https://your-nakama-host/v1/auth/oidc/callback`. In local development this is `http://localhost:3003/v1/auth/oidc/callback` (the web port), or `http://localhost:4310/v1/auth/oidc/callback` for a Docker install.

## Setup

Set these environment variables and restart Nakama:

```sh
NAKAMA_OIDC_ISSUER_URL=https://id.example.com
NAKAMA_OIDC_CLIENT_ID=nakama
NAKAMA_OIDC_CLIENT_SECRET=your-client-secret
NAKAMA_OIDC_PROVIDER_NAME=Pocket ID
```

`NAKAMA_OIDC_ISSUER_URL` turns SSO on — the issuer URL of your provider, without a trailing slash (Pocket ID uses `https://your-pocketid-host`, with no path). `NAKAMA_OIDC_PROVIDER_NAME` is only the button label; it defaults to `SSO`.

A partial config fails the server at startup rather than showing a button that cannot work, so a typo surfaces immediately.

Then decide who gets an account:

```sh
NAKAMA_OIDC_AUTO_PROVISION=true
NAKAMA_OIDC_DEFAULT_ORG=acme
NAKAMA_OIDC_ALLOWED_DOMAINS=acme.com,acme.dev
```

- `NAKAMA_OIDC_AUTO_PROVISION` creates a Nakama account on first SSO sign-in. Off (the default) means only accounts that already exist can sign in — create them first through the normal invite flow, and the first SSO login links the provider identity to that account.
- `NAKAMA_OIDC_DEFAULT_ORG` is the organization slug new accounts join. An invite for the same email wins over the default org. With neither an invite nor a default org, provisioning is refused.
- `NAKAMA_OIDC_ALLOWED_DOMAINS` is a comma-separated list of accepted email domains (subdomains count). Leave it empty only when the provider itself restricts who may sign in — Nakama warns at startup if you auto-provision with no allowlist.

## Optional settings

```sh
NAKAMA_OIDC_ADMIN_GROUPS=nakama-admins
NAKAMA_OIDC_GROUPS_CLAIM=groups
NAKAMA_OIDC_SCOPES="openid email profile groups"
NAKAMA_OIDC_REQUIRE_EMAIL_VERIFIED=true
NAKAMA_OIDC_DISABLE_PASSWORD_LOGIN=true
NAKAMA_OIDC_LINK_EXISTING_ACCOUNTS=true
NAKAMA_OIDC_REDIRECT_URL=https://your-nakama-host/v1/auth/oidc/callback
```

- `NAKAMA_OIDC_ADMIN_GROUPS` promotes a signing-in user to platform admin when their provider groups match, and demotes them when the group is removed. The very first account on an install is never demoted — it stays your break-glass. Groups come from `NAKAMA_OIDC_GROUPS_CLAIM` (default `groups`); make sure your scopes request it.
- `NAKAMA_OIDC_REQUIRE_EMAIL_VERIFIED` (default on) rejects accounts whose email the provider has not verified. Leave it on unless your provider does not send that claim.
- `NAKAMA_OIDC_DISABLE_PASSWORD_LOGIN` hides and refuses email+password and passkey sign-in for everyone except the first account, which remains the emergency way in.
- `NAKAMA_OIDC_LINK_EXISTING_ACCOUNTS` (default on) links a provider login to an existing Nakama account when the verified email matches. Turn it off if you want admins to provision identities explicitly.
- `NAKAMA_OIDC_REDIRECT_URL` overrides the callback URL Nakama tells the provider. You almost never need this — it is derived from the origin the browser actually used — unless the dashboard sits behind a split host that cannot carry the callback.

## Pocket ID example

In Pocket ID, create an OIDC client with the callback URL above and note the client ID and secret. Set `NAKAMA_OIDC_ISSUER_URL` to your Pocket ID base URL and `NAKAMA_OIDC_PROVIDER_NAME=Pocket ID`. To map Pocket ID user groups to Nakama platform admins, allow the `groups` scope on the client and set `NAKAMA_OIDC_ADMIN_GROUPS` to your admin group's name.

## How sign-in resolves the account

1. Nakama first looks for a stored link between the provider's issuer+subject pair and a user. Found means that user signs in — an email change at the provider does not create a second account.
2. Otherwise it matches the verified email to an existing account and links it (when linking is enabled).
3. Otherwise it provisions a new account — into a pending invite's org, the default org, or the first organization on an empty install.

Each provider identity links to exactly one account; each account can hold links to several identities. The sign-in handshake itself is single-use and expires after ten minutes, so a pasted callback URL cannot be replayed.
