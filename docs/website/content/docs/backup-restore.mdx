## Export

Platform admins can export local Nakama data from **Settings → Export ZIP**.

The export is a `.zip` backup of the configured Nakama data root, which defaults to `~/.nakama` and follows `NAKAMA_CONFIG_DIR` when set.

Treat export ZIPs as sensitive. They can include:

- Provider settings and API keys
- Auth data
- Org and profile workspaces (soul files, memory, artifacts)
- Org-level `MEMORY.md`, `memory-archive/`, and `memory-history/` (see [Org memory](/org-memory))
- Custom tools and skills
- Plugin packages and organization plugin data (snapshotted, not copied mid-write)
- The local SQLite database when it lives under the Nakama root

## Import

Importing is a whole-install restore:

1. Preview the ZIP first
2. Confirm restore to replace the current local data root

Plan for downtime during restore. This replaces the active data root rather than merging individual records.

On a fresh install, you can also restore during [first-time setup](/first-time-setup) before creating a new admin account.

On Windows, preview the ZIP in Nakama, then stop the server and any workers before restoring. Live restore is unavailable because Windows cannot replace an open database file. Keep the ZIP **outside** the Nakama data directory. From the repository, with the same `NAKAMA_CONFIG_DIR` and `DATABASE_URL` used by the server, run:

```bash
bun run restore:offline --yes "C:\backups\nakama-export.zip"
```

Restart Nakama after the command succeeds. The command refuses to restore while a server using that data directory holds the restore lock, or when its database is outside the backed-up data directory. Keep the ZIP until you have checked the restarted install.

Restored plugins stay **disabled** until an organization admin enables them on **System → Plugins**. If a restored package no longer matches its stored hash, that release stays unavailable and must be installed again.

## Profile packs (single agent)

To move **one** profile without a full-root backup, use **System → Profiles → Export profile / Import profile**. See [Profiles → Export and import a profile pack](/profiles#export-and-import-a-profile-pack).

Those packs deliberately omit secrets and are not interchangeable with Export ZIP above.

## Docker volumes

When Nakama runs in Docker, persist `/nakama/data` with a named volume or bind mount. Back up that volume (or use Export ZIP from the dashboard) before upgrades or migrations.

To restore a ZIP with a stopped container, mount the ZIP read-only in a temporary Nakama container using the same data volume, then restart the main container:

```bash
docker stop nakama
docker run --rm --entrypoint bun -v nakama-data:/nakama/data -v /absolute/path/to/backup.zip:/backup.zip:ro ghcr.io/ahmadrosid/nakama:latest run restore:offline --yes /backup.zip
docker start nakama
```

Replace the volume name and ZIP path if yours differ. Restart only after the restore command succeeds.

See [Docker](/docker) for volume setup.
