## Why plugins exist

Skills and custom tools cover one piece of a feature. A plugin ships the whole feature: a dashboard page, agent tools, and the data they share — without changing Nakama itself.

## What you get

After a package is approved and your organization turns it on:

- Members open native plugin pages from the sidebar, using the dashboard theme
- Assigned profiles can call the plugin's tools in chat
- Notes and other plugin records stay in that organization

The same note you create on the page is the one the agent reads. Another organization never sees it.

## How to use them

**1. Install a package (platform admin).** Open **System → Plugins**, enter the public npm package name and exact version, choose **Preview package**, review what it declares, and install it. Installation stores the package. It does not run plugin code and does not turn the plugin on for any organization.

**2. Activate it in the organization (org admin).** Still on **System → Plugins**, add the plugin to the active organization, then enable it. Enable is what creates the organization's data store and makes the page available.

**3. Assign capabilities (platform admin).** Use the existing profile skill and tool pickers. Plugin items show as owned by the plugin. Assign them the same way you assign other skills and tools.

**4. Use the page (members).** Open the plugin from the sidebar Plugins group. Viewers can read chat only — they cannot open plugin pages or call plugin actions.

**5. Update or remove (org admin).** Disable the plugin first. Then pick an approved newer release and update, or uninstall. Uninstall keeps the organization's plugin data until you confirm a separate delete.

## Supermemory

Keep an agent's saved facts and reference documents available across conversations. The Supermemory plugin adds separate **Memory** and **Knowledge** collections for each agent.

1. An org admin opens **System → Plugins → Official plugins → Supermemory → Install**.
2. Open **Supermemory → Settings** and save your server URL and API token. Use **Check saved connection** to verify access.
3. Choose an agent. Use **Remember** for a fact, or **Knowledge → Add text** to paste text or select a UTF-8 `.txt` or `.md` file up to 256 KiB.
4. A platform admin assigns the plugin skill and tools to that agent to use them in chat. Ask it to remember a fact or search a saved document.

The plugin connects to a separately managed [Supermemory server](https://supermemory.ai/docs/self-hosting/quickstart#bunx). Configure OpenAI for extraction and embeddings on that server using the [provider settings](https://supermemory.ai/docs/self-hosting/configuration) and [embedding settings](https://supermemory.ai/docs/self-hosting/embeddings). Content processed by OpenAI leaves your local server.

Saves are explicit. Installing this plugin does not automatically capture conversations or move existing Nakama memory and knowledge. Source links are citations; the plugin does not fetch them. PDFs must be extracted to text separately.

Documents show their processing state. Use **Check status** for an unresolved save and retry the same submission when asked. **Removal pending** means the item is excluded from plugin searches, but remote removal still needs retry. **Forget** is a soft deletion upstream, not permanent erasure.

Use a dedicated Supermemory server per organization. Once content has been saved, the plugin keeps that server address fixed; an admin can still rotate its token. Disabling or uninstalling retains the external data. Back up the Supermemory server separately: Nakama's backup contains the connection and tracking records, not the external dataset. Restore into the same organization to retain access; moving records to a different organization requires fresh ingestion.

## Who can do what

| Action | Who |
|---|---|
| Install or remove a package | Platform admin |
| Enable, disable, update, uninstall, delete retained data | Org admin |
| Open plugin pages and call plugin actions | Members and admins |
| View plugin pages or invoke plugin actions | Viewers cannot |

## Trust

An installed plugin is trusted code. Approving a package lets that code run with the signed-in user's dashboard session and the server process. Organization folders keep one org's notes away from another org by accident. They do not protect you from a malicious plugin author.

## Backup

Plugin data is included in a full **Settings → Export ZIP** backup as a consistent snapshot. Restore leaves plugins disabled until an admin enables them again. If a restored package no longer matches its stored hash, that release stays unavailable.

See [Backup and restore](/backup-restore).
