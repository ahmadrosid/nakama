Open **Control center → Integrations** to manage settings that span agents or the whole installation.

## Available sections

- [Notifications](/telegram/notifications): send agent events to Telegram groups and forum topics
- [Composio](/composio): connect SaaS toolkits with per-user OAuth and assign them to agents
- **Coding agents**: choose Nakama provider passthrough or host login — see [Coding agent](/coding-agent#provider-passthrough)
- **Context savings**: configure token optimization and review its savings — see [Token optimiser](/token-optimiser)
- [Error tracking](/error-tracking): send this instance's crashes to your Sentry, GlitchTip, or Bugsink project

Channel credentials and bridge workers belong to the selected agent. Open **Agent → your agent → Channels**, then choose the channel. Telegram, WhatsApp, Discord, and Slack use `/profiles/:profileId/channels/:channel`. MCP servers are separate; see [MCP servers](/mcp).

## Backend API keys

Use organization backend API keys when a server-side app needs to call Nakama's AI API. Create them from the organization admin API, store the returned secret in that app's server-side environment, and send it as `Authorization: Bearer <key>`.

The secret is shown only when the key is created or rotated. Nakama stores a hash, so list keys to see metadata and revoke or rotate compromised keys. Do not put these keys in browser code, mobile apps, or public repositories. The existing `~/.nakama/local-auth-token` remains for local CLI and worker access.

## What lives in Integrations

Integrations group settings that are not tied to one agent's channel configuration. Common examples include:

- notification destinations
- Composio projects, app enablement, and per-user OAuth
- coding-agent provider passthrough
- context optimization settings
- error-reporting credentials
