# Teams Direct Messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Let an org admin connect a Teams bot to one agent and answer allowed personal chats.

**Architecture:** The public API forwards authenticated Teams traffic to a loopback SDK worker. Configuration, session mappings, access checks and worker state belong to one org/profile. Reuse existing channel utilities.

**Tech Stack:** Bun 1.4+, TypeScript, Hono, React, Teams SDK 2.1.1, existing SQLite adapter.

**Spec:** ../specs/2026-10-27-teams-dm-design.md, approved by Viko on 27 October 2026.

## Global Constraints

- Branch feat/2081-teams-dm; no Co-authored-by. Preserve #2086.
- SDK 2.1.1; worker on 127.0.0.1, ephemeral port, image exposes one public port.
- Personal text messages only. No pairing, commands, group/channel replies, files, or automation delivery.
- Admin settings, explicit user allowlist, fixed owner, no secret in public responses/logs, no authentication bypass.
- No Microsoft tenant is available. Local fixture tests do not prove a real Teams round trip.
- Eventual PR needs new-package label. New handwritten files stay below 5,000 approximate tokens.

## Review Focus

- Spoofed org/profile/tenant inputs cannot reroute a message: Tasks 1–3 tests.
- Invalid replacement credentials preserve working configuration: Task 1 tests.
- A stale port after worker death never receives forwarded traffic: Task 2 tests.
- Long turns and duplicate delivery do not create duplicate live turns: Task 3 tests.
- Missing HTTPS configuration does not appear as a working endpoint: Task 4 tests.
